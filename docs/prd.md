## 1. 目标与范围

### 1.1 目标

业务用**结构体 + `dbx` 标签**声明一张表的读写语义，运行时由反射生成 SQL：

- 列名、零值策略、默认值、自增主键、查询条件**声明式**表达 —— 业务不写手写 SQL、不散落反射调用、不感知方言；
- 核心 SQL 是**标准 SQL**，方言差异（标识符引用、占位符、分页写法、取回自增值、参数上限）全部收在 dbwm；
- **建表不推导**：表结构由业务手写 SQL 编排成脚本目录，由 migration 按水位执行并留痕；
- 业务拿到的是行模型（`*T` / `[]*T`）与执行统计，不是 SQL 文本。

一句话概括：**业务给"表模型 + 条件结构体"，框架把它变成能在各数据库上跑的语句。**

### 1.2 在范围内

| # | 范围项 |
| --- | --- |
| S1 | 业务门面 `slyorm.Collection`：单表增删改查、分页列表、事务 |
| S2 | 读写语义解析：`dbx` 标签 → 列清单、条件树、写入值形态 |
| S3 | SQL 渲染与执行：IR、方言、扫描目标、事务 |
| S4 | 数据迁移：按水位执行业务 SQL 脚本目录并留痕 |
| S5 | 扩展点注册：自定义选项、默认值函数、算子、审计列 |

### 1.3 不在范围内

| 不在范围 | 去向 |
| --- | --- |
| JOIN、跨表条件、子查询 | 后续需求 |
| 分组 / 聚合 / HAVING 的门面入口 | dbwm 的 IR 与执行已具备（prd-dbwm R4），用到时再加 |
| Upsert、行级锁、软删、乐观锁 | 后续需求（prd-dbwm §1.3） |
| 从模型生成 DDL / 表结构推导 | **不做**（prd-slyorm §1.3 维持）；建表与初始化由业务手写 SQL，migration 按水位执行（prd-migration） |
| 连接池管理、驱动注册 | 调用方（本库不 import 任何驱动，见 prd-dbwm R9.2） |
| 日志打点 | 框架内不打点：执行统计以返回值交给业务，业务自己记（prd-slyorm §1.3） |

## 2. 分层与调用链

```
business ─┬─→ slyorm（门面） ──→ dbwm ──→ sql.DB
          └─→ migration ──────→ dbwm
```

| 层 | 归属 | 职责 | 硬约束 |
| --- | --- | --- | --- |
| 业务层 | 调用方 | 表模型、条件结构体、SQL 脚本目录 | 不出现在框架内部 |
| 门面层 | 根包 `slyorm` | `Collection` 表访问器、`DB` 句柄、通用类型、审计列 | 唯一 import 全部能力包的一层；不含 SQL 文本与方言判断 |
| 能力层 | `model` / `query` / `insert` / `rows` / `migration` | 各管一种语义的解析与成形 | 互不 import；产出模型元信息、dbwm 的 IR，或经 dbwm 执行 |
| 中间层 | `dbwm` | IR、方言、渲染、执行、扫描、事务 | 不认识 dbx，不认识业务模型 |
| 工具层 | `util` | 标签文本处理、取值与零值判定、`Range[T]` | 不认识业务语义 |
| 驱动层 | `database/sql` + 驱动 | 连接与语句执行 | 驱动由调用方注册 |

依赖方向单向向下：门面 → 能力 → 中间层 → 工具层。**能力层之间不横向依赖** —— 共同需求下沉到工具层，或由门面组装。

### 2.1 内部导入关系（当前代码）

| 包 | 导入的内部包 |
| --- | --- |
| `util` | 无 |
| `dbwm` | 无（只用标准库） |
| `model` | `util` |
| `query` | `dbwm`、`util` |
| `insert` | `dbwm`、`model`、`util` |
| `select`（包名 `rows`） | `dbwm`、`model` |
| `migration` | `dbwm` |
| 根包 `slyorm` | 全部 |

| 包 | 一句话职责 | 落地 | 详规 |
| --- | --- | --- | --- |
| `slyorm`（根包） | 业务门面：`Collection` 单表访问、`DB` 句柄、分页协议、通用类型、审计列、`Migrate` 转发 | `slyorm.go` / `collection.go` / `collection_helper.go` / `list.go` / `types.go` / `audit.go` / `migrate.go` | [prd-slyorm.md](prd-slyorm.md) |
| `model` | 列名推导的**唯一入口**：静态列集合、主键标记、路径 | `model/` | [prd-slyorm.md §7](prd-slyorm.md) |
| `rows`（`select/`） | 行模型投影计划、RowFactory、扫描目标（NULL 兜底 / 时间兼容 / JSON） | `select/` | [prd-slyorm.md §6](prd-slyorm.md) |
| `query` | 读规则：条件结构体 → `*dbwm.Wnode`（值成形：like 补 %、区间展开） | `query/` | [prd-select.md](prd-select.md) |
| `insert` | 写规则：模型 → `*dbwm.Insert` / `Update` IR 与执行入口 | `insert/` | [prd-insert.md](prd-insert.md) |
| `migration` | 数据迁移：按水位执行业务 SQL 脚本目录并留痕（`sys_migration`） | `migration/` | [prd-migration.md](prd-migration.md) |
| `dbwm` | SQL 渲染与执行、方言、事务（连接接口归它所有） | `dbwm/` | [prd-dbwm.md](prd-dbwm.md) |
| `util` | 共用工具：标签文本处理、取值与零值判定、`Range[T]` | `util/` | —— |

`insert` 可独立使用（自带 `DB` 句柄与表名推导机制 `TableName()` / `RegisterTable` / 类型名 snake_case）；门面的 `Collection` 走构造期显式表名，同一模型可映射多张表。

## 4. 需求条目

### R1 声明式读写语义

**需求**：一张表的读写语义由"结构体 + `dbx` 标签"声明，不写手写 SQL。

**规则**：

1. 表模型 M 声明表的可访问面：列集合与主键从声明推导；列名推导只有一条路径（`model` 包），insert 与 select 共用，不各写一份；
2. **写规则与读规则是两套互不干涉的规则集**，共用 `dbx` 一个标签键（[prd-insert.md](prd-insert.md) / [prd-select.md](prd-select.md)）；
3. 业务代码里不出现 SQL 文本、不散落反射调用、不出现方言判断；
4. 标签里的未知选项**忽略但保留**（DDL 侧、查询侧的选项不污染写包）；重复选项与语义冲突在解析期报错；
5. 表名与模型解耦：门面在构造期显式传入，同一模型可映射多张表。

**验收**：模型标签写错在构造期或首次使用时当场报错，不留到数据库才炸。

### R2 分层与依赖方向

**需求**：包边界一眼可辨，替换下层实现不改上层。

**规则**：

1. 一个能力一个包，包名 = 目录名 = 能力名（唯一例外：行模型读取在 `select/`、包名 `rows` —— `select` 是 Go 关键字）；
2. 能力层互不 import；门面是唯一 import 全部能力包的一层；
3. 具体连接类型（`*sql.DB` / `*sql.Tx`）只出现在 `dbwm` 的适配器与各 `NewSQL` 形参里，其余层只见 `dbwm.Conn` / `dbwm.Tx` 接口；
4. **不开逃生舱**：不提供"取回底层 `*sql.DB`"的方法 —— 注入连接的一方自己留句柄；
5. 工具层不认识业务语义；能力层不反向 import 门面。

**验收**：`*sql.DB` / `*sql.Tx` 只出现在 `dbwm` 的适配器与各 `NewSQL` 形参里；能力包之间无 import。

### R3 依赖注入与事务

**需求**：连接、方言由调用方决定；事务只以 ctx 传递。

**规则**：

1. 连接以接口形态注入（`dbwm.New(conn, opts...)`）；`Open` / `NewSQL` 是便利构造，根包原样转发；
2. **方言是构造选项**（`dbwm.WithDialect`）：不给选项时用 ANSI 方言；`Open` 传 nil 方言时按驱动名映射、映射不到再探测库型，识别不出来报错（不猜）；
3. 事务只用 ctx 传递（`db.Tx(ctx, fn)`）：fn 收到的 ctx 自动带事务，嵌套调用复用外层事务，由最外层提交或回滚；事务结束后该 ctx 上的调用报错，绝不静默改走连接池；
4. 驱动由调用方注册，本库不 import 任何驱动。

**验收**：嵌套两层 `Tx` 只开一个事务；回调返回后用其 ctx 调用报错。

### R4 方言适配

**需求**：新增数据库只加方言，业务代码不动。

**规则**：

1. 核心 SQL 是标准 SQL；方言只管标准 SQL 覆盖不到的少数几点：标识符引用、占位符、分页写法、取回自增值的方式、参数上限；
2. 方言判断不散进业务逻辑（收敛在 dbwm 的渲染器与策略表）；
3. 值一律走绑定参数，不拼进语句文本；动态标识符必须经引用或白名单（排序列白名单由门面校验）。

**验收**：同一条查询在 ANSI / MySQL / PostgreSQL 下渲染出各自认的语句。

### R5 扩展点注册

**需求**：业务能扩语义，不改框架代码。

**规则**：

1. 扩展点集中在注册表：自定义选项（`insert` / `query`）、默认值函数（`insert`）、自定义算子（`query` 归约为核心算子，dbwm 只兜不可归约的算子）、审计列当前用户（根包 `RegisterUser`）；
2. 注册发生在 init 期；**破坏不变量的调用一律 panic**（非法入参、重名、覆盖内置）；
3. 注册必须在对应模型第一次被解析之前完成（模型元信息按类型缓存，之后再注册对已缓存模型无效）；
4. 默认值函数的**存在性与类型匹配在取值时校验**（模型解析不查函数表）：报错带字段名与函数名。

**验收**：重复注册 panic；未注册 `deff` 函数时 Create / Update 报错并指出字段与函数名。

### R6 建表与初始化脚本

**需求**：建表与结构修补能按序执行、可重复启动、留痕可查。

**规则**：

1. **不从模型生成 DDL、不做表结构推导** —— 建表、初始化、结构修补语句由业务手写 SQL 编排成脚本目录（embed 进二进制）；
2. migration 按水位执行：脚本名 `{版本号}_{序号}_{名称}.sql`，一脚本一事务，成功记录与脚本同事务提交，失败留痕且失败即停（失败即停是失败可重试的前提）；
3. 脚本**原样整发**给驱动：不解析、不改写、不拆分；`dbwm.ExecScript` 是原样执行 SQL 的唯一入口；
4. 执行记录表固定 `sys_migration`，mgx 时代存量表零改动兼容。

**验收**：同一脚本目录连续跑两次，第二次零留痕；脚本失败时正文效果不落库且留 `success=0` 的记录。

### R7 错误、日志与缓存

**需求**：写错了能立刻定位；热路径无重复解析。

**规则**：

1. 错误信息带**包名前缀 + 中文说明 + `%w` 包装**：说明要指出哪个模型 / 哪列 / 哪条规则不满足，不写"参数错误"这类无信息的话；
2. **框架内不打日志**：执行统计以返回值交给业务（迁移返回 `Stats`），日志由业务记；
3. 解析结果按类型缓存（模型元信息、投影计划、条件模板、默认值注册表）；构建失败**不缓存**错误，重复调用重复报错。

**验收**：错误信息能定位到模型与列；同一个错误连续两次调用两次都报错。

### R8 文档先行与测试纪律

**需求**：需求、实现、测试三处对得上。

**规则**：

1. 每个能力先有 PRD，PRD 里编号的需求条目（R1、R2…）是实现与测试的依据；代码注释用编号互引；
2. 测试同包白盒；验证真实 SQL 行为用内存 SQLite + 手写建表，断言"执行了哪条 SQL"用替身连接；
3. 提交前跑 `go vet ./...` 与 `go test ./...`，并跑分层与错误格式的自检 grep。

**验收**：每条需求条目至少有一个对应测试，测试名体现规则本身。

## 7. 明确不做

- 不写兼容层、弃用别名、双路径实现 —— 旧设计可以直接改掉；
- 不引入第三方 ORM / 查询构建库 —— 语义由本项目自己的 PRD 定义；
- 不从模型生成 DDL、不做表结构推导 —— 建表 / 初始化 / 结构修补由业务手写 SQL 编排成脚本目录，`migration/` 按水位执行；
- 不把驱动、连接池、事务实现泄漏进业务逻辑；
- 不在框架内打日志；
- 新能力先写 PRD，再写实现。
