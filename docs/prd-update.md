## 1. 目标与范围

### 1.1 目标

业务给**要改的列和值**（模型或投影）+ **改哪些行**（条件结构体），框架生成 `UPDATE` 并执行：

- 改哪些列、写成什么值，由模型声明（`dbx` 标签 + 写规则），不写手写 SQL；
- 改哪些行由**读规则**的条件结构体表达 —— 与查询同一套语法与算子；
- **零值是有效值**（清零是合法意图），"这一列不动"在全量 `Update` 下由**投影类型**表达（投影里不声明这一列），单个字段也可以用 `omit` 表达（零值不进 `SET`，见 R10）；
- 审计列这类"每次更新都刷"的列由默认值函数（`deff=`）自动补值；
- 更新**必须带条件** —— 无条件更新一律拒绝。

### 1.2 在范围内

1. **SET 列的判定** —— 哪些列进 `UPDATE ... SET`（R2）；
2. **值的落库形态** —— 零值 / SQL `NULL` / 指针 / JSON 列 / `inline` 展开的子列（R3）；
3. **默认值在更新时的语义** —— `deff=` 生效、`defv=` 不生效（R4）；
4. **定位条件** —— 条件树构造、列集合校验、拒绝无条件更新（R5）；
5. **主键剔除** —— 主键列不进 SET（R6）；
6. **局部更新** —— 投影类型表达"只改这几列"（R7）；
7. **执行、事务与错误** —— 渲染、事务、错误分类（R8）；
8. **返回值语义** —— 更新返回什么（R9）；
9. **`omit` 的参与** —— 零值列不进 `SET`（R10）。

### 1.3 不在范围内

| 不在范围 | 去向 |
| --- | --- |
| 批量更新（一条语句更新多行、每行不同的值） | 后续需求（§10 待拍板 3） |
| Upsert / `ON CONFLICT` | 后续需求（prd-dbwm §1.3 已列为不做） |
| 乐观锁 / 版本号（`WHERE` 带版本，影响行数为 0 判冲突） | 待拍板（§10 待拍板 1） |
| 字段级表达式更新（`col = col + 1`） | 后续需求（§10 待拍板 4） |
| 软删、状态机流转 | 业务侧语义，框架不做 |
| 删除（`DELETE`） | 门面的 `Delete` 语义见 [prd-slyorm.md](prd-slyorm.md) R9（尚未单列 PRD） |
| 建表 / DDL | **不做** —— 由业务手写 SQL，经 `db.Migrate` 执行（prd-migration） |

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| **表模型 M** | `Collection` 构造时绑定的结构体：列集合与主键集合的来源 |
| **投影 T** | 更新时传入的结构体类型：只含要改的列（可以是与 M 不同的类型） |
| **条件 Q** | 读规则的条件结构体，解析成 `WHERE` 条件树 |
| **SET 列** | 进 `UPDATE ... SET` 的列 |
| **值形态** | 一个字段落库时的具体值：Go 零值 / SQL `NULL` / 序列化后的 JSON 字符串 |
| **主键集合** | M 里标了裸 `pk` 或 `autopk` 的列 —— 剔除 SET 用（`pk=组名` 的组名不认） |
| **零值** | 字段的 Go 零值（`0` `""` `nil`）；`time.Time` 用 `IsZero()` 判定（口径见 prd-insert R4） |

## 3. 分层与职责边界

```
业务 → slyorm.Collection.Update（组织：条件 → SET → 执行）
                     ↓
        insert.BuildUpdateIR（写规则解释 + 值成形）
                     ↓
        dbwm.Update（IR）→ dbwm.DB.Update（渲染 + 执行）
```

| 层 | 职责 | 不做 |
| --- | --- | --- |
| `insert` | 值成形：SET 列清单、值的落库形态、默认值补值、`omit` 跳列 | 不填表名（IR 的 `Table` 留空）、不剔除主键、不管 `Where` |
| `slyorm`（根包） | 组织：条件解析、投影列集合校验、主键剔除、组装 IR、调用执行 | 不拼 SQL、不解释值形态 |
| `dbwm` | `Update` IR 的定义、渲染、执行、事务、错误分类 | 不认识 `dbx`、不认识投影 |
| `model` | 列名推导与主键标记（**唯一入口**，insert 与 select 共用） | —— |
| `query` | 条件解析（读规则）→ 条件树 | —— |

**UPDATE 没有独立的能力包**：写规则解释与值成形与 INSERT 是同一套（同一批选项、同一套零值语义），拆出去等于复制一份写规则。两者只有三处差别，本 PRD 记全：

1. `deff=` 生效、`defv=` 不生效（R4）；
2. 主键列不进 SET —— 由门面按 M 的主键集合剔除（R6）；
3. 没有"零值交给数据库生成"这回事 —— `autopk` 列照常进 SET，再被主键剔除规则去掉（R2 / R6）。

## 4. 需求条目

### R1 更新入口与职责切分

**需求**：业务只调一个方法，框架内部把"改哪些列"和"改哪些行"分开处理。

**规则**：

1. 门面入口：`Update[Q, T](ctx context.Context, q *Q, p *T) error` —— `q` 是条件（读规则），`p` 是要写的列和值（写规则）；
2. 一次更新的处理顺序固定：**投影形态校验 → 条件解析 → 值成形（SET 列与值）→ 投影列集合校验 → 主键剔除 → 组装 IR → 执行**；
3. 投影 `T` **不能是指针**（与读侧同款）—— 指针形态在 IR 构造前拦下，不给误导性的下游错误；
4. 写侧的 IR 构造入口 `insert.BuildUpdateIR(ctx, v)` 是**公开**的：投影可以是匿名结构体（表名与条件由调用方填），门面复用同一个入口，不另写一套值成形；
5. SQL 文本只由 `dbwm` 渲染 —— 门面与 `insert` 包不出现 SQL 片段。

**验收**：

- `users.Update(ctx, &bo.UserIDQuery{ID: 1}, &bo.UserUpdate{Name: "新名"})` → 只 `SET name`；
- 投影是指针 → 报错"投影类型 X 不能是指针"；
- 直接调 `insert.BuildUpdateIR` 得到的 IR 里 `Table` 与 `Where` 为空（由调用方填）。

### R2 SET 列的判定

**需求**：哪些列进 `SET`，必须可预期。

**规则**：

1. **SET 列 = 投影类型的静态列清单**（字段声明序，`inline` 按字段位置展开）—— 与 INSERT 同一套列推导（`model` 包是唯一入口）；
2. **零值也是有效值**：投影里的列全部进 `SET`，值为零就写零值（清零是合法意图）—— **`omit` 列除外**，见 R10；
3. 不进 `SET` 的只有四种：
   - `dbx:"-"` 的字段；
   - 未标注 `dbx` 的字段（连列名都不推导）；
   - **M 的主键列**（`pk` / `autopk`）—— 由门面剔除，见 R6；
   - **`omit` 列且值为零** —— 由写侧的值成形剔除，见 R10；
4. `inline` 展开的子列**各自成列**、各自进 `SET` —— 嵌套结构不是一列，更新时不是整体替换：某个子列值为零就写那个零值；
5. `json` 列是**一列**，进 `SET` 时整列被新值覆盖（序列化后的 JSON 字符串，见 R3）；
6. **列清单是模型的静态属性**，不随值变化 —— 值形态（`NULL` / 零值 / JSON）只影响绑定值，不影响列清单；**唯一的例外是 `omit` 列**（按值判定进不进 `SET`，见 R10）。

**验收**：

- 投影 `UserUpdate{Name string; Status int}` → `SET` 列 = `[name, status]`，`status` 传 `0` 也进 `SET`（值为 `0`）；
- 投影里有 `dbx:"-"` 字段 → 该列不进 `SET`；
- `inline` 子结构里某个子列零值 → 该子列照进 `SET`、值为零值。

### R3 值的落库形态

**需求**：字段值到列值的映射与 INSERT 一致 —— 同一份模型不该有两套零值语义。

**规则**（与 INSERT 同款，差别点单独列出）：

1. 标了 `null` 的列，值为零 → SQL `NULL`；
2. 指针字段为 `nil` → SQL `NULL`（不需要 `null` 选项）；指针非 `nil` 且指向零值 → 写那个零值（"显式赋过零值"）；
3. `json` 列 → 整个值序列化成 JSON 字符串；`*T` 且为 `nil` → SQL `NULL`；序列化后的形态由该类型自己的 `json` 标签决定（不是 `dbx` 标签）；
4. 其余 → 原值绑定；
5. **与 INSERT 的一条差别**：更新没有"零值交给数据库生成"这回事 —— 零值就是零值，不会触发列的 `DEFAULT`；列的 `DEFAULT` 只有在该列不进语句时才有机会生效（更新里做不到"不写这一列"，除非用投影少声明一列，见 R7）；
6. 写侧的值类型不匹配（如 JSON 序列化失败）按 [prd-error.md](prd-error.md) R5 归类为 `KindTypeMismatch`，业务侧可用 `slyorm.IsTypeMismatch` 判定。

**验收**：

- `Age int \`dbx:"age,null"\`` 传 `0` → `SET age=NULL`；
- `Name *string` 传 `nil` → `SET name=NULL`；传 `&""` → `SET name=''`；
- `json` 列传新结构体 → 整列被覆盖为序列化结果。

### R4 默认值在更新时的语义

**需求**：审计列这类"每次更新都要刷"的列能自动补值。

**规则**：

1. `deff=`（默认值函数）在更新时**生效**：字段为零值时调用函数，取值**写回结构体**并写入该列；非零值不覆盖（调用方显式指定优先）；
2. `defv=`（字面量默认值）在更新时**不生效** —— 静态常量没有"更新时刷新"的语义；
3. 默认值与 `null` 同时存在时**默认值优先**（与 INSERT 同款）：补完不再是零值，写的是默认值而不是 `NULL`；
4. 审计列的典型写法：`UpdatedAt time.Time \`dbx:"updated_at,deff=now"\``、`UpdatedBy int64 \`dbx:"updated_by,deff=curuser"\`` —— `curuser` 由门面的 `slyorm.RegisterUser` 提供（见 [prd-slyorm.md](prd-slyorm.md) R12）；
5. 要"每次更新都刷新"的列，**更新投影里不要赋值**（保持零值），`deff` 才会补；
6. 函数未注册 / 执行失败 → 报错并指出**函数名与字段名**（取值时校验，不在模型解析期）。

**验收**：

- 投影含 `UpdatedAt` 且为零值 → 更新后结构体的 `UpdatedAt` 非零，库里存的是同一个值；
- 投影给了非零 `UpdatedAt` → 不被默认值覆盖；
- `defv=18` 的列在更新时保持零值（不补 18）。

### R5 定位条件（`WHERE`）

**需求**：更新必须限定范围 —— 全表更新是误操作的主要来源。

**规则**：

1. 条件 `q` 按**读规则**解析（`query` 包）成条件树 —— 与查询同一套语法、算子与值成形（见 [prd-select.md](prd-select.md)）；
2. 条件里的列必须在**表模型 M** 的列集合里（不在 → 报错，错误带列名与表名）；
3. **无条件更新一律拒绝**：条件取值后为空（所有字段都没值，或被 `omit` 跳过）→ 报错，错误带表名与操作名。两道防线：
   - **门面先拦** —— 业务侧错误，提示"缺少过滤条件"；
   - **dbwm 兜底** —— IR 的 `Where` 为空时渲染期报错，防止绕过门面直接用 `dbwm` 造成全表更新；
4. 条件可以是复合条件（与 / 或 / 组合），语义与查询一致；
5. 同一列可以同时出现在 `SET` 与 `WHERE` 里（如"把 status 从 1 改成 2"：`SET status=2 WHERE status=1`）；
6. 框架**不隐式补主键条件** —— 条件完全由调用方给。

**验收**：

- `q` 为 `nil` 或全零值 → 报错"缺少过滤条件"，错误带表名与操作名；
- 直接构造 `dbwm.Update{Table: "t", Columns: [...], Values: [...]}`（`Where` 为空）→ dbwm 渲染期报错。

### R6 主键剔除

**需求**：主键不该被更新。

**规则**：

1. **主键集合只认表模型 M** —— M 里标了裸 `pk` 或 `autopk` 的列（`pk=组名` 的组名不认，复合主键用多个裸 `pk` 表达）；
2. 剔除发生在**门面**（`Collection.Update`）：`SET` 的列与值成对剔除主键列；
3. **投影自带的 `pk` 标记不参与剔除判定** —— 否则用投影就能绕过剔除（把主键列留在 `SET` 里）。投影里标了 `pk` 但 M 里没标的列，按**普通列**处理，照常进 `SET`；
4. `autopk` 列同样剔除 —— 更新不改自增主键（也不回填任何生成值，更新没有自增可取）；
5. 剔除后 `SET` 为空 → 报错（"无可更新字段"），不发出空 `SET` 的语句；
6. `insert.BuildUpdateIR` 单独使用时**不剔除主键** —— 剔除需要 M 的主键集合，而 IR 构造只看到投影类型；由调用方（门面）负责。

**验收**：

- M 的主键列出现在投影里 → 不出现在 `SET`；
- 投影全部由主键列组成 → 报错"无可更新字段"；
- 投影把某个普通列标成 `pk`（M 里它不是主键）→ 该列照常进 `SET`。

### R7 "不更新某列"的表达

**需求**：只改一部分列，并且能明确表达"这一列不动"。

**规则**：

1. 局部更新靠**投影类型**：另定义一个只含要改的列的结构体（如 `bo.UserUpdate{Name string}`），更新时传它；
2. **"不更新某列"通常由"投影里不声明这一列"表达** —— 没有"只更新非零字段"的开关，也不存在"字段为 `nil` 就跳过"这类按值裁剪列清单的行为（列清单是静态属性，见 R2.6）；**唯一的例外是 `omit`** —— 声明了但值为零时该列不进 `SET`（见 R10）；
3. 指针字段表达的是"这一列写 `NULL`"（`nil`）或"写这个值"（非 `nil`），**不是**"不写这一列"；
4. 投影的列必须在 M 的列集合里（不在 → 报错，带投影类型名、列名与表名）；校验在**值成形之后**做（列清单由投影类型决定）；
5. 投影**不必是 M 的子集类型** —— 投影的标签按写规则解释，列名照常推导（`col=` / 字段名 snake_case）；
6. M 与投影对同一列的标签可以有差别，但 M 是**列集合校验**与**主键剔除**的依据。

**验收**：

- 投影只含 `Name` → `SET` 只有 `name`；
- 投影里的 `*string` 为 `nil` → `SET name=NULL`（不是"不更新 name"）；
- 投影含 M 里没有的列 → 报错，错误带投影类型名、列名与表名。

### R8 执行、事务与错误

**需求**：更新在事务里原子，错了能定位。

**规则**：

1. 渲染由 `dbwm` 负责，语句形态：`UPDATE "<表>" SET "<列1>"=?,... WHERE <条件>`；
2. **表名与列名加引号**（引号风格由方言决定），**值一律走绑定参数**；占位符形式由方言决定（SQLite / MySQL `?`，PostgreSQL `$1,$2,…`）；
3. 事务：更新走 ctx 上的事务（`db.Tx(ctx, fn)`），嵌套复用外层；更新与其它写入同事务即原子；
4. 执行错误经 `dbwm` 包装成 `*dbwm.Error`（带类别 / 约束名 / 出错语句），业务侧用根包判定接口处理（见 [prd-error.md](prd-error.md) R4）—— 典型：更新命中唯一索引 → `slyorm.IsUnique(err)` 为真 → 提示"已存在"；
5. **框架自身的错误不是数据库错误**：空条件、投影越界、无可更新字段 → `slyorm.ErrorKind(err)` 返回 `KindUnknown`；
6. 更新**不回填任何字段** —— 没有自增值要取回；`deff` 补的值只写回**调用方传入的投影结构体**（不是表模型 M）。

**验收**：

- 唯一索引冲突 → `slyorm.IsUnique(err)` 为真，`ConstraintOf` 给出冲突的索引名 / 列；
- 空条件 → `ErrorKind` 为 `KindUnknown`，错误信息带表名与操作名；
- 事务内更新后回滚 → 数据未变。

### R9 返回值

**需求**：更新返回什么，业务据此判断。

**规则**：

1. `Update` **只返回 `error`** —— 影响行数不上浮（与门面的其它写入口同款，见 [prd-slyorm.md](prd-slyorm.md) 已拍板 16）；
2. **条件没命中任何行不算错误** —— 返回 `nil`；业务要区分"更新了 0 行"目前做不到（见 §10 待拍板 2）；
3. 不返回"更新了哪几行"之类的信息 —— 更新不产生新行。

**验收**：

- 条件命中 0 行 → 返回 `nil`，不报错；
- 条件命中多行 → 全部被更新，返回 `nil`。

### R10 `omit`：零值不进 SET

**需求**："这一列这次不改"要能在**字段级**表达 —— 投影里声明了列，但值是零值时这一列不进 `SET`，库里原值保持。

**规则**：

1. `omit` 是**列级选项**：字段标签里写了 `omit`（裸 flag 或显式布尔），该列在写侧的值成形阶段按"零值当成没有值"处理 —— 与读规则的同名选项同一口径（prd-select R1）；
2. **零值口径**与写规则一致（prd-insert R4 的零值表）：基本类型零值、`nil` 指针、空切片 / 空映射、零值 `time.Time`（`IsZero()`）、零值结构体；**非 nil 指针指向零值不算零值**（"显式赋过零值"，照常进 `SET`）；
3. **只影响 UPDATE 的 `SET` 列清单** —— INSERT 的列清单恒定（prd-insert R4.1：批量插入各行列清单必须一致，一条 INSERT 只有一份列清单），因此 INSERT 不认这个语义，`omit` 列在 INSERT 里照常写入；
4. **零值判定在默认值补齐之后**：带 `deff=` 的列先补默认值（补完不再是零值）→ 照常进 `SET` —— 审计列"每次更新都刷新"的语义不被 `omit` 吃掉；
5. **与 `null` 的分工**：`null` 决定"写什么"（零值写 `NULL`），`omit` 决定"写不写"（零值不写）；两者同时存在时 `omit` 优先 —— 零值的 `omit` 列不进 `SET`，不写 `NULL`；
6. **与主键剔除的先后**：先按值剔除 `omit` 列（写侧的值成形），再由门面剔除主键列（R6）；两者都判完后 `SET` 为空 → 报错（"没有可更新的列" / "无可更新字段"）；
7. **不推翻 R2.6 的静态性**：`SET` 列清单仍是"投影的静态列清单"，只是标了 `omit` 的列按值参与判定 —— 这是唯一的例外。

**验收**：

- `Name string \`dbx:"name,omit"\`` 传 `""` → `SET` 里没有 `name`，库里原值保持；
- 同一列传 `"新名"` → `SET name='新名'`；
- `Nick *string \`dbx:"nick,omit"\`` 传 `nil` → 不进 `SET`；传 `&""` → 进 `SET`，值为空串；
- `Age int \`dbx:"age,omit,null"\`` 传 `0` → 不进 `SET`（不写 `NULL`）；
- `At time.Time \`dbx:"at,omit,deff=now"\`` 传零值 → 补默认值后进 `SET`；
- 投影的列全部是 `omit` 且值为零 → 报错（没有可更新的列）；
- 同一模型走 INSERT → `omit` 列照常进列清单。

## 5. 字段 → 是否参与 SET 对照表

| 字段形态 | 是否进 SET | 值 |
| --- | --- | --- |
| 普通字段，值非零 | ✅ | 该值 |
| 普通字段，值零 | ✅ | Go 零值（清零是合法意图） |
| 普通字段 + `null`，值零 | ✅ | SQL `NULL` |
| 普通字段 + `null`，值非零 | ✅ | 该值 |
| 指针字段，为 `nil` | ✅ | SQL `NULL` |
| 指针字段，非 `nil` 指向零值 | ✅ | 那个零值（"显式赋过零值"） |
| 有 `deff`，值零 | ✅ | 先调默认值函数补值（写回结构体） |
| 有 `deff`，值非零 | ✅ | 原值，不调函数 |
| 有 `defv`，值零 | ✅ | **不补** —— 保持零值（`defv` 在更新时不生效） |
| `json` 字段 | ✅ | 整列，值是序列化后的 JSON 字符串 |
| `json` 字段（`*T`），为 `nil` | ✅ | SQL `NULL` |
| `inline` 子列 | ✅ | 各子列独立进 SET，零值照写 |
| `omit` 列，值零 | ❌ | 不进 SET，原值保持（R10） |
| `omit` 列，值非零 | ✅ | 该值 |
| `omit` + `deff`，值零 | ✅ | 先调默认值函数补值（补完不再是零值，R10.4） |
| M 的主键列（`pk` / `autopk`） | ❌ | 门面剔除（R6） |
| `dbx:"-"` | ❌ | 完全忽略 |
| **未标注 `dbx`** 的字段 | ❌ | 整个字段忽略（连列名都不推导） |

> 表是**全量 SET 模式**的对照。投影里不声明的列不进 `SET`；声明了但标了 `omit` 且值为零的列也不进 `SET`（R10）。

## 6. API 一览

| 符号 | 位置 | 说明 |
| --- | --- | --- |
| `Collection.Update[Q, T](ctx, q *Q, p *T) error` | 根包 `slyorm` | 更新入口：条件 + 投影 |
| `insert.BuildUpdateIR(ctx, v any) (*dbwm.Update, error)` | `insert` | 模型 / 投影 → `UPDATE` IR（`Table`、`Where` 留空由调用方填） |
| `type Update struct` | `dbwm` | IR：`Table` / `Columns` / `Values` / `Where` |
| `(*DB).Update(ctx, up *Update) (Result, error)` | `dbwm` | 渲染 + 执行（`Result.RowsAffected` 在 dbwm 层可见，门面不向上传递） |

```go
// 只改一列：投影只声明要改的列（Update 是全量 SET 语义，投影之外的列不进 SET）
err := users.Update(ctx, &bo.UserIDQuery{ID: 1}, &bo.UserUpdate{Name: "新名"})
// → UPDATE "users" SET "name"=? WHERE "id"=?

// 单列"这次不改"：omit + 零值 → 该列不进 SET，原值保持
// （bo.UserRemarkUpdate.Remark 的标签是 dbx:"remark,omit"）
err = users.Update(ctx, &bo.UserIDQuery{ID: 1}, &bo.UserRemarkUpdate{Remark: ""})
```

## 8. 已知限制

1. **影响行数不上浮** —— 业务拿不到"更新了几行"，乐观锁判冲突做不了（§10 待拍板 1）；
2. **条件没命中不报错** —— 返回 `nil`，"以为改了其实没改"要靠业务自己查（§10 待拍板 2）；
3. **全量 `Update` 不按值裁剪列清单** —— "不更新某列"的表达是投影里不声明这一列；单列的"这次不改"用 `omit` + 零值（R10）；
4. **不支持表达式更新** —— `col = col + 1` 这类自增列语义表达不了（§10 待拍板 4）；
5. **不支持批量更新** —— 一条 `UPDATE` 只能带一组列值（§10 待拍板 3）；
6. **主键不可更新** —— 主键集合只认 M，M 里是主键的列在更新里永远被剔除（R6）；
7. **`insert` 包没有独立的 UPDATE 执行入口** —— 只有 `BuildUpdateIR`；独立使用者自己填 `Table` 与 `Where` 再调 `dbwm.DB.Update`；
8. **PG / MySQL 未做真库验证** —— 当前验证以内存 SQLite + 替身连接为主（与 [prd-dbwm.md](prd-dbwm.md) §8 一致）。

## 9. 已拍板

1. **UPDATE 不另起能力包** —— 写规则解释与值成形复用 `insert` 包（同一套选项、同一套零值语义），拆包等于复制一份写规则；
2. **全量 `Update` 的 SET 列 = 投影的静态列清单** —— 零值也是有效值，不按值裁剪列清单（`omit` 列是唯一的例外，R10）；
3. **主键剔除在门面** —— 按 M 的主键集合判定，投影自带的 `pk` 标记不作数（否则能用投影绕过剔除）；
4. **`deff=` 生效、`defv=` 不生效** —— 函数默认值能"每次更新刷新"，静态常量没有这个语义；
5. **无条件更新拒绝** —— 门面拦 + dbwm 兜底两道防线；
6. **`Update` 只返回 `error`** —— 影响行数不上浮（与门面其它写入口同款）；
7. **错误分类复用 prd-error 的类别与判定接口** —— 不另起一套。
8. **`omit` 只在 UPDATE 生效** —— 零值列不进 `SET`（R10）；INSERT 的列清单恒定（批量插入要求各行列清单一致），不认这个语义；与读规则的同名选项同口径："零值当成没有值"。

---

## 10. 待拍板

1. **影响行数是否上浮** —— 上浮后可以做乐观锁（`WHERE` 带版本号，影响行数为 0 判冲突）；不上的话业务只能自己查；
2. **条件没命中任何行要不要报错** —— 当前返回 `nil`；报错能挡住"以为改了"，但会让"条件本来就匹配不到"的正常流程变成异常；
3. **批量更新与 Upsert 的排期** —— 批量更新（多行不同值）要不要一条语句、要不要自带事务；
4. **字段级表达式更新**（`col = col + 1`、`col = col + ?`）—— 表达不了计数类语义；
5. **更新要不要从 `insert` 包拆出去** —— 当前不拆；若将来批量更新 / Upsert 的规则变复杂，再评估独立成包。
