## 1. 目标与范围

### 1.1 目标

用**一个条件结构体 + `dbx` 标签**描述 WHERE 片段，由 ORM 反射生成 SQL 条件与绑定参数：

- 条件"查哪一列、怎么比、零值要不要忽略"**声明式**表达，不手写 SQL；
- 结构体字段**分组**（`inline` + `comb=and|or|not`），组的括号形态确定、可预期；
- 区间用**类型**表达（`Range[T]`，左闭右开），放进 `or` 组不会被拆散；
- 值一律走**绑定参数**；没有任何生效条件时不生成 WHERE 子句；
- 算子可由业务**注册扩展**；引号与占位符由方言决定，与写规则共用同一套方言。

一句话概括：**`dbx` 标签在读规则下只描述三件事 —— 查哪一列（列名）、怎么比（算子）、零值要不要忽略（`omit`）；比什么值从结构体字段里取，取到"没有值"就不加这条条件。**

### 1.2 在范围内

| # | 范围项 |
| --- | --- |
| S1 | 条件结构体 → 条件树模板（解析期，按类型缓存） |
| S2 | 条件树模板 + 运行期取值 → WHERE 片段 + 绑定参数 |
| S3 | 区间类型 `Range[T]` 的语义 |
| S4 | 算子表与算子扩展点 |
| S5 | 分组（括号）的组织方式 |

### 1.3 不在范围内

| 不在范围 | 去向 |
| --- | --- |
| SELECT 列清单的推导、扫描回结构体 | 已落地：`model/`（列名推导）与 `select/`（包名 `rows`，投影与扫描），见 [prd-slyorm.md](prd-slyorm.md) |
| JOIN、跨表条件 | 后续需求（会改变"列名允许重复"等前提） |
| GROUP BY / 聚合 / 排序 / 分页 | 后续需求（`sort=` `agg=` 已在读规则词汇表里预留） |
| UPDATE / DELETE 的 WHERE | **复用本文的规则**（主键组定位另议） |

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| **条件模型** | 用于查询过滤的结构体，按**读规则**解析 `dbx` 标签（与"行模型"分开） |
| **叶子** | 标量 / 指针 / 切片字段产生的单个条件，生成 `"col" <op> ?` |
| **条件组** | 写了 `inline` 的结构体字段；子条件按 `comb` 连接，整体用 `()` 包裹 |
| **算子** | `op=` 指定的比较方式（`eq` / `like` / `in` / …），省略时按字段类型推断 |
| **参与** | 一条条件是否出现在 WHERE 里 —— 由"有没有值"与 `omit` 共同决定（见 R1） |
| **没有值** | 指针为 nil、切片/数组为空、`sql.Null*` 无效、`Range` 两端皆零 —— 这些形态**天然跳过** |
| **精确匹配** | 默认语义：字段有值就生成条件，**零值也是一个值**（`id = 0` 也是条件） |
| **条件树模板** | 条件结构体解析后的静态结构（字段 → 列名 / 算子 / 分组关系），**不含值**；按类型缓存、跨方言复用（见 R6.5） |
| **`Range`** | 半开区间类型 `Range[T]{Min, Max}`，生成 `("col" >= ? AND "col" < ?)` |

## 3. `dbx` 标签语法（读规则子集）

### 3.1 语法与解析规则

```
dbx:"<列名>[,<选项>...]"
选项 := 标识符 | 标识符 "=" 值
```

1. **首段是列名**（叶子字段）：`col=` 显式指定优先；首段为空时用字段名的 snake_case。**组字段的首段不参与计算** —— 组不是一个列；
2. 选项统一 `key=value`；**只有分组的三个连接词**（`and` / `or` / `not`）提供裸 flag 别名，等价于 `comb=<值>`。其余选项（含 `op=`）必须写全 —— 避免与将来的列级选项（`sort=` `agg=` 等）抢命名空间；
3. 按逗号切分，**括号与引号内的逗号不切分**；每段先去掉两端空白；
4. 引号**成对出现**才是分组标记，外层引号脱掉，值按给定保留（只脱外层引号，不做大小写转换）；
5. 选项名转小写；**同一选项重复出现 → 解析期报错**（视为笔误，不做"后者覆盖前者"）；
6. `dbx:"-"` → 该字段完全不参与；
7. **未标注 `dbx` 的字段直接忽略** —— 不产生任何条件，也不报错；
8. 非导出字段不参与；
9. **读规则不认识的选项一律"忽略但保留"**，不报错、不阻断：
   - 写规则专属的选项（`null` `autopk` `deff` `defv` …）在条件模型里出现 —— 按未知选项处理；
   - 完全未知的选项 —— 同上。保留下来是为了文档生成器、DDL 生成器还能读到"这里写过什么"。

> 裸 flag 的取值等价于 `true`；显式取值接受 `true/false/1/0/yes/no/on/off`（大小写不敏感）。

### 3.2 选项总表（读规则）

| 选项 | 作用域 | 取值 | 含义 |
| --- | --- | --- | --- |
| `col=` | 叶子 | 串 | 显式列名（读写通用） |
| `op=` | 叶子 | 算子名 | 比较算子；可省略，按字段类型推断（见 R4） |
| `omit` | 叶子 | bool | **零值当成没有值**：字段值为零值时整条条件跳过（默认零值是参与匹配的） |
| `comb=` | 组 | `and` / `or` / `not` | 组内条件如何连接；默认 `and` |
| `inline` | 组 | bool | **必须写**：结构体字段不写 `inline` 一律忽略（等同 `dbx:"-"`） |

- 裸 `and` / `or` / `not` 是 `comb=` 的别名：`dbx:",inline,or"` ≡ `dbx:",inline,comb=or"`；
- **`omit` 是读写共用的选项**，同一口径："零值当成没有值" —— 读侧是整条条件跳过，写侧是这一列不进 `SET`（[prd-update.md](prd-update.md) R10）；它在 INSERT 里不生效（列清单恒定）；
- `omit` 只能写在**叶子字段**上；写在组字段上 → 解析期报错（组是否参与由子条件决定）；
- `omit` 对 `Range` 字段与 `op=isnull` / `op=notnull` 字段**没有额外效果**（前者的参与由两端零值决定，后者由布尔值决定）—— 解析期不报错，也不改变行为；
- 组字段上只认 `inline` 与 `comb=`；`op=` / `omit` 写在组字段上 → 解析期报错（见 R7）。

### 3.3 与写规则的关系

两套规则共用**一个标签键** `dbx`，按"这个结构体在这次调用里扮演什么角色"分裂：

1. **规则集由 API 入口决定** —— `query.BuildWhere()` 走读规则，`insert.Insert()` 走写规则；
2. **元信息按 `(类型, 规则集)` 缓存**，两套规则互不干扰：同一个结构体既当行模型又当条件模型也不会串味；
3. **跨规则选项只忽略、不报错**（保留到 `Opts`，供文档生成器、DDL 生成器读取）：

| 选项 | 条件模型（读规则） | 行模型（写规则） |
| --- | --- | --- |
| `op=` `comb=` | ✅ 生效 | 忽略但保留 |
| `omit` | ✅ 生效 | ✅ 生效 —— 只在 UPDATE 的 SET 阶段（零值列不进 `SET`），INSERT 不生效 |
| `inline` `col=` | ✅ 生效 | ✅ 生效 |
| `null` `autopk` `deff` `defv` | 忽略但保留 | ✅ 生效 |
| 完全未知的选项 | 忽略但保留 | 忽略但保留 |

## 4. 需求条目

每条需求以 **需求 / 规则 / 验收** 三段式给出。

### 4.1 条件模型

#### R1 字段参与：精确匹配、`omit` 与"没有值"

**需求**：每个条件字段都要有确定的"是否参与"判定。

**规则**：

1. **默认语义是精确匹配**：字段有值就生成条件，**零值也是一个值**（`id = 0`、`flag = false`、`name = ''` 都会进 WHERE）；
2. 想让某个字段的**零值**被忽略，写 **`omit`** —— 它把这个字段的零值当成"没有值"，整条跳过；
3. **"没有值"只有四种天然形态**：指针为 nil、切片/数组为空、`sql.Null*` 无效、`Range` 两端皆零 —— 这些一律跳过，写不写 `omit` 都一样；
4. 指针语义：**nil = 没有值；非 nil 指向零值 = 显式赋过零值**（参与，`&""` → `nick = ''`）；
5. `op=isnull` / `op=notnull` 是**布尔开关**：字段为 `true` 才加条件，`false` / `nil` 不加；字段类型必须是 `bool` / `*bool`，否则解析期报错（见 R7）；
6. **可选过滤器用指针字段**：想"不填就是不过滤"就写 `*T`；只想让零值被忽略又不想改字段类型，写 `omit`。

**完整判定表**（"有没有值"与 `omit` 两件事共同决定参与）：

| 字段形态 | 有没有值 | 默认（无 `omit`） | 写了 `omit` | 参与时绑定的值 |
| --- | --- | --- | --- | --- |
| 标量，零值（`0` `""` `false`） | 有 | ✅ 参与（`col = 0`） | ❌ 跳过 | 值本身 |
| 标量，非零 | 有 | ✅ | ✅ | 值本身 |
| 指针，nil | **没有** | ❌ | ❌ | —— |
| 指针，非 nil（指向零值） | 有 | ✅ | ❌ 跳过 | 指向的值 |
| 指针，非 nil（指向非零） | 有 | ✅ | ✅ | 指向的值 |
| 切片 / 数组，空 | **没有** | ❌ | ❌ | —— |
| 切片 / 数组，非空 | 有 | ✅ | ✅ | 每个元素一个占位符（`in` / `nin`） |
| `[]byte`，空 | **没有** | ❌ | ❌ | —— |
| `[]byte`，非空 | 有 | ✅ | ✅ | 整个字节串（按 `eq`，不按 `in`） |
| `sql.Null*`，`Valid == false` | **没有** | ❌ | ❌ | —— |
| `sql.Null*`，`Valid == true`（含内容为零） | 有 | ✅ | 内容为零 → ❌；否则 ✅ | `Valid` 携带的值 |
| `time.Time`，`IsZero()` 为真 | 有 | ✅ 参与（绑定零时刻） | ❌ | 值本身 |
| `Range[T]`，两端都零值 | **没有** | ❌ | ❌（无额外效果） | —— |
| `Range[T]`，一端或两端非零 | 有 | ✅（只生成非零的那侧） | ✅（无额外效果） | 非零端的值 |
| `op=isnull` / `op=notnull`（`bool` / `*bool`） | —— | **true 才加**，false / nil 不加 | （无额外效果） | **不绑值** |

**验收**：

- ``ID int `dbx:"id"`` ``，`ID == 0` → WHERE 里有 `"id" = ?`（参数 0）；
- ``Name string `dbx:"name,omit"`` ``，`Name == ""` → 整条消失；
- ``Nick *string `dbx:"nick"`` ``，nil → 消失；`&""` → `"nick" = ?`（参数空串）；
- ``Flag *bool `dbx:"flag,omit"`` ``，nil / `&false` → 消失；`&true` → 参与；
- ``Del bool `dbx:"deleted,notnull"`` ``，false → 消失；true → `"deleted" IS NOT NULL`（无绑定参数）。

#### R2 列名推导与列名重复

**需求**：每个叶子条件都要有确定的列名；列名允许重复。

**规则**：

1. `col=<值>` 显式指定（优先级最高）；
2. 否则取 `dbx` 标签首段；
3. 否则取字段名的 snake_case（`CreatedAt` → `created_at`）；
4. 首段与 `col=` **同时**给出 → 解析期报错（列名重复指定）；
5. **组字段没有列名** —— 组不是列，其标签首段在读规则下被忽略；
6. **列名允许重复** —— WHERE 是条件列表，不是列清单（写规则的"列名不得重复"只约束列清单）：
   - 同一列配**不同算子**是常态（`op=gte` + `op=lte` 表达闭区间）；
   - 同一列 + **同一算子**重复也放行（刻意叠条件是合法用法）；
7. 列名必须匹配 `[A-Za-z_][A-Za-z0-9_]*`，否则解析期报错（见 R7，防注入）。

**验收**：`From *time.Time `dbx:"created_at,op=gte"`` + `To *time.Time `dbx:"created_at,op=lte"`` → 两条平级条件，不报错。

### 4.2 分组

#### R3 条件组（`inline` 与 `comb`）

**需求**：多个条件要能组成 `AND` / `OR` / `NOT` 的嵌套组合。

**规则**：

1. 结构体字段**必须显式写 `inline`** 才会被解析成条件组，否则整个字段忽略（等同 `dbx:"-"`）；
2. `comb=` 决定组内连接方式，默认 `and`；裸 `and` / `or` / `not` 是它的别名；
3. `comb=` **只能出现在组字段上**，叶子字段写 `comb=` → 解析期报错；
4. 组字段上只认 `inline` 与 `comb=`：`op=` / `omit` 写在组字段上 → 解析期报错；写规则专属选项按未知选项处理（忽略但保留）；
5. **组一律用 `()` 包裹**（不看连接方式）；顶层那层隐式 AND **不额外包裹**，WHERE 后面直接跟条件；
6. 只有一个子条件的组也照常包裹（`(a)`）；**没有任何生效子条件的组整个不参与**（连括号一起消失）；
7. `not` 组的形态是 `NOT (...)`，组内子条件仍按 AND 连接后整体取反；
8. 组可以任意嵌套；嵌套组的括号由内向外逐层生成。

| `comb=` | 组内条件 | 生成的形态 |
| --- | --- | --- |
| `and`（默认） | 全部 AND 连接 | `(a AND b AND c)` |
| `or` | 全部 OR 连接 | `(a OR b OR c)` |
| `not` | AND 连接后取反 | `NOT (a AND b)` |

**验收**：

```go
type PersonQuery struct {
    CreatedAt *util.Range[time.Time] `dbx:"created_at"`
    Any       struct {
        Name string `dbx:"name,op=like"`
        City string `dbx:"city"`
    } `dbx:",inline,comb=or"`
}
```

→ `("created_at" >= ? AND "created_at" < ?) AND ("name" LIKE ? OR "city" = ?)`；
`Any` 组内全为零值 → 该组连同括号消失。

### 4.3 算子

#### R4 比较算子（`op=`）

**需求**：每个叶子条件都要有确定的比较方式。

**规则**：

1. `op=` 统一写全（`op=eq`）。**裸 flag 形式不认**：`dbx:"name,like"` 里的 `like` 是未知选项（忽略但保留），算子仍按类型推断成 `eq` —— 想用 `like` 必须写 `op=like`；
2. **算子省略时按字段类型推断**（按**解引用后**的元素/字段类型）：

| 字段类型（解引用后） | 推断算子 |
| --- | --- |
| `Range[T]` / `*Range[T]` | `range` |
| 切片 / 数组（`[]byte` 除外） | `in` |
| 其余（标量、指针、`[]byte`、`sql.Null*`） | `eq` |

3. 算子取值必须是**已注册的算子**（核心表 + `RegisterOperator` 注册的），否则解析期报错并列出合法取值；
4. **算子与字段类型必须匹配**（见 R7 校验清单）；
5. **`op=regex` 是 `op=like` 的别名**：解析期归一化成 `like`，同一套处理、同样的 `%` 规则 —— 各数据库正则语法不同（SQLite 无原生 `REGEXP`），与其给一个"一半数据库不认"的算子，不如映射到 `like`；真正要正则，注册自己的算子（见 R8）。

**算子总表**：

| 算子 | 生成的 SQL | 值的要求 | 说明 |
| --- | --- | --- | --- |
| `eq` | `"col" = ?` | 标量 / 指针 / `[]byte` / `sql.Null*` | **默认算子**；`[]byte` 按整串比较；切片配 `eq` 报错 |
| `ne` | `"col" <> ?` | 标量 / 指针 | |
| `gt` | `"col" > ?` | 标量 / 指针 | |
| `gte` | `"col" >= ?` | 标量 / 指针 | |
| `lt` | `"col" < ?` | 标量 / 指针 | |
| `lte` | `"col" <= ?` | 标量 / 指针 | |
| `like` | `"col" LIKE ?` | 字符串 / `*string` | 见下方通配符规则 |
| `in` | `"col" IN (?,?,…)` | 切片 / 数组（`[]byte` 除外） | 元素逐个绑定；空切片不生成条件 |
| `nin` | `"col" NOT IN (?,?,…)` | 切片 / 数组（`[]byte` 除外） | 同上 |
| `isnull` | `"col" IS NULL` | `bool` / `*bool` | **布尔开关**：true 才加；不绑值（见 R1.5） |
| `notnull` | `"col" IS NOT NULL` | `bool` / `*bool` | 同上 |
| `range` | `("col" >= ? AND "col" < ?)` | `Range[T]` / `*Range[T]` | 由类型推断得到，手写 `op=range` 也允许 |

**`like` 的通配符规则**：值里**没有 `%` 时补成 `%值%`（包含匹配）**；已带 `%` 的**原样保留** —— 调用方自己写的模式不被改写。

| 值 | 生成的模式 | 匹配 |
| --- | --- | --- |
| `"a"` | `"%a%"` | 包含 a |
| `"a%"` | `"a%"` | 以 a 开头 |
| `"%a"` | `"%a"` | 以 a 结尾 |
| `"%a%"` | `"%a%"` | 包含 a |

> 为什么默认包含匹配：`LIKE` 最常见的用途是搜索框的模糊匹配；单向补 `%`（如"以值结尾"）是最少用的语义，静默反向最难排查。四种匹配都能表达：默认包含、开头/结尾自己补 `%`。
> `isnull` / `notnull` 不复用 `eq`：SQL 里 `= NULL` 恒不成立，把"和 NULL 比"塞进 `eq` 会制造经典陷阱 —— 按 NULL 过滤就用这两个明确的算子。

**验收**：

- ``Name string `dbx:"name,op=like"`` ``，`Name == "张"` → `"name" LIKE ?`，参数 `"%张%"`；`Name == "张%"` → 参数原样 `"张%"`；
- ``IDs []int64 `dbx:"id"`` ``（省略 op）→ `"id" IN (?,?,…)`；
- `op=xyz` → 解析期报错并列出可用算子；
- `op=in` 用在 `string` 上 → 解析期报错（类型不匹配）。

### 4.4 区间

#### R5 `Range[T]`：左闭右开区间

**需求**：时间/数值窗口用一个字段表达，且作为整体参与组合。

**规则**：

1. `Range` 是**类型**承载的语义，不是标签选项：

   ```go
   // 包 util（写规则也要认识它：Range 是单列类型，不展开）
   type Range[T any] struct {
       Min T
       Max T
   }
   ```

2. 语义**左闭右开**：`("col" >= ? AND "col" < ?)` —— 时间窗口的通行约定：查"10 月"用 `[10-01, 11-01)`，不漏 10-31 23:59:59，也不与相邻窗口重叠；
3. 边界由**类型零值**决定：`Min` 是零值 → 不生成下界；`Max` 是零值 → 不生成上界；两端都零值（或指针为 nil）→ 整个条件不参与；
4. `Range[T]`（值）与 `*Range[T]`（指针）都认，指针为 nil → 不参与；
5. 字段类型是 `Range[T]` 时推断出算子 `range`；显式写 `op=range` 允许（结果一致），写**其它**算子 → 解析期报错；
6. **`Range` 是一个组**：整体用 `()` 包裹 —— 放进 `or` 组不会被拆散。如果用两个普通字段（`op=gte` + `op=lt`）表达同一区间，它们是两个平级叶子，放进 `or` 组会变成 `(col >= ? OR col < ?)` —— 语义直接错。这是 `Range` 存在的第一个理由；
7. 零值判定沿用写规则那一套（含 `time.Time` 用 `IsZero()`）；
8. **为什么不用 `op=between`**：SQL 的 `BETWEEN` 是**闭区间**（`>= AND <=`），和左闭右开不是一回事，叫 `between` 会误导；且类型把两端的类型绑死（`Range[time.Time]` 不会出现"下界 time、上界 int"的错配），一个字段顶两个字段、类型可复用。

**需要其它边界语义**（闭区间、单向开区间）用两个普通字段表达 —— 列名允许重复（见 R2.6）：

```go
type PersonQuery struct {
    From *time.Time `dbx:"created_at,op=gte"`
    To   *time.Time `dbx:"created_at,op=lte"`
}
```

→ `"created_at" >= ? AND "created_at" <= ?`（两个平级叶子，不构成组、无括号）。

**验收**：

- `CreatedAt *util.Range[time.Time]`，`Min` 与 `Max` 都给了 → `("created_at" >= ? AND "created_at" < ?)`，参数按 `Min`、`Max` 顺序绑定；
- 只有 `Min` → `("created_at" >= ?)`（单端也照常包裹，见 R6.2）；
- 两端皆零 / nil → 整条消失；
- `*util.Range[time.Time]` 上写 `op=eq` → 解析期报错。

### 4.5 语句生成

#### R6 WHERE 片段生成

**需求**：生成的 WHERE 片段必须可预期，且值一律走绑定参数。

**规则**：

1. 顶层条件按 **AND** 连接，**不加外层括号**；片段**不含 `WHERE` 关键字**（拼装由查询侧完成）；
2. **组与 `Range` 一律用 `()` 包裹**（不看连接方式；`Range` 只剩一端时也照常包裹 —— 括号形态不随数据变化，这是"可预期"的一部分）；`not` 组为 `NOT (...)`；
3. **没有任何生效条件 → 返回空片段**（调用方据此不拼 `WHERE`；不要 `1=1` 那种骨架）；
4. **所有值都是绑定参数**，不拼进 SQL 字符串；`isnull` / `notnull` 不绑参数；
5. 列名引用（`"` 或 `` ` ``）与占位符（`?` 或 `$1,$2…`）由**方言**决定；**条件树模板存原始列名** —— 模板按类型缓存、跨方言复用，引号在**运行期**由方言加；
6. **参数顺序 = 片段中占位符从左到右的出现顺序**，与占位符一一对应；
7. 生成过程纯内存计算、无 IO。

**验收**：

```go
type PersonQuery struct {
    ID        int64                 `dbx:"id"`
    Name      string                `dbx:"name,op=like"`
    Age       int                   `dbx:"age,omit"`
    CreatedAt *util.Range[time.Time] `dbx:"created_at"`
}
q := &PersonQuery{ID: 7, Name: "%a%", CreatedAt: &util.Range[time.Time]{Min: from, Max: to}}
```

→ 片段 `"id" = ? AND "name" LIKE ? AND ("created_at" >= ? AND "created_at" < ?)`，参数 `[7, "%a%", from, to]`（`Age` 零值 + `omit` → 消失）。

### 4.6 校验

#### R7 解析期校验清单

**需求**：写错了要能立刻定位。

以下都在**第一次解析该条件结构体时**报错，错误信息带上结构体名 + 字段名 + 正确写法：

| # | 规则 | 错误示例 |
| --- | --- | --- |
| 1 | `op=` 取值必须是已注册算子 | `op=xyz` → "未知算子 xyz（可用：eq, ne, gt, …）" |
| 2 | 算子与字段类型必须匹配 | `op=in` 用在 `string` 上 → "op=in 需要切片字段" |
| 3 | `like` 要求字符串字段 | `op=like` 用在 `int` 上 → "op=like 需要字符串字段" |
| 4 | `eq` 不接受切片字段 | `op=eq` 用在 `[]int` 上 → "op=eq 不支持切片字段" |
| 5 | 显式 `op=` 与类型推断冲突 | `*Range[time.Time]` 上写 `op=eq` → "range 字段不能配 op=eq" |
| 6 | `isnull` / `notnull` 要求 `bool` / `*bool` | 用在 `int` 上 → "op=isnull 需要布尔字段（true 才加条件）" |
| 7 | `comb=` 只能出现在组字段上 | 叶子字段写 `comb=or` → "comb= 只能用在组字段上" |
| 8 | `comb=` 取值必须是 and/or/not | `comb=xor` → "未知组合方式 comb=xor（可用：and、or、not）" |
| 9 | `op=` 只能出现在叶子字段上 | 组字段写 `op=eq` → "op= 只能用在叶子字段上" |
| 10 | 同一选项重复出现 | `dbx:"id,op=eq,op=like"` → "选项 op 重复" |
| 11 | 列名重复指定 | `dbx:"id,col=other"` → "列名重复指定（首段与 col= 只能写一个）" |
| 12 | 列名必须是合法标识符 | `dbx:"id;drop"` → 报错（防注入） |
| 13 | `[]byte` 不能配 `in` / `nin` | → "op=in 不支持 []byte（它按 eq 处理）" |
| 14 | `omit` 只能写在叶子字段上 | 组字段写 `omit` → "omit 只能用在叶子字段上（组是否参与由子条件决定）" |

**不报错**的情况：

- 组字段没写 `inline` → 整个字段忽略（等同 `dbx:"-"`）；
- 未标注 `dbx` 的字段 → 直接忽略（见 3.1.7）；
- 写规则的选项（`null` `autopk` `deff` `defv`）出现在条件模型里 → 忽略但保留；
- 完全未知的选项 → 忽略但保留；
- 同一列出现多次（**含同一列 + 同一算子**）→ 放行（见 R2.6）；
- `omit` 写在 `Range` / `isnull` / `notnull` 字段上 → 无效果，不报错（见 3.2）。

### 4.7 扩展

#### R8 扩展点

**需求**：核心算子表不够用时，业务能自己加。

**规则**：

1. **算子注册**：`RegisterOperator(name, fn)` 新增 `op=` 取值（如 `contains`、`startswith`、真·正则）；
   算子实现的职责：**给方言、原始列名与取值，产出 SQL 片段与绑定参数**（引号由算子通过方言加）；
2. **选项注册**：`RegisterOption(key, handler)` 注册读规则作用域的业务自定义选项 —— 处理器拿到叶子条件的元信息（`Cond`），可以读选项、改算子；
3. **注册时机**：算子与选项都在**解析期**被校验，因此注册必须发生在该条件模型**第一次被解析之前**；
4. **方言**：实现 `Dialect` 接口（引号 / 占位符，与写规则共用，见 §8）；
5. **其它区间语义**（闭区间、单向开区间）用两条平级叶子表达（列名允许重复，见 R2.6），或注册自定义算子实现 —— 本文只定义 `Range` 一种区间类型。

```go
// 核心算子表里没有 contains，需要时自己注册：
query.RegisterOperator("contains", func(d util.Dialect, col string, v any) (string, []any, error) {
    return d.QuoteIdent(col) + " LIKE ?", []any{"%" + fmt.Sprint(v) + "%"}, nil
})
```

**验收**：注册后 ``Note string `dbx:"note,op=contains"`` `` 立即可用，参与规则与核心算子一致。

## 5. API 一览

```go
import "github.com/icdb37/slyorm/query"   // 包名 query：select 是 Go 关键字，不能作包名
import "github.com/icdb37/slyorm/util"    // Range 等共享类型（SQL 方言在 dbwm，本包不再需要方言）

// 解析条件结构体 → 条件树模板（按类型缓存，可复用；只看类型，与值无关）
tpl, err := query.ParseWhere(&PersonQuery{})

// 模板 + 条件值 → dbwm 条件树；没有任何生效条件时返回 nil（调用方据此不加 WHERE）
w, err := tpl.Build(ctx, &PersonQuery{...})
// w = &dbwm.Wnode{Comb: CombAnd, Items: [...]}   —— 交给 dbwm.Query.Where

// 模板出现过的全部列名（含本次取值可能不参与的），供上层对着表模型校验列存在性
cols := tpl.Columns()

// 算子扩展（见 R8）：定义为「语义 + 值成形」，归约为核心算子组合，不拼 SQL 片段
query.RegisterOperator("prefix", func(col string, v any) (*dbwm.Wcond, error) {
	return &dbwm.Wcond{Column: col, Op: dbwm.OpLike, Arg: fmt.Sprint(v) + "%"}, nil
})
query.RegisterOption("tenant", handler)

// 区间类型（放在 util）
r := util.Range[time.Time]{Min: from, Max: to}
```

- **值成形在本包**（like 补 `%`、区间展开、空集合跳过），**语法在 dbwm**（算子关键字、引号、占位符，见 prd-slyorm §3）—— 本包产出 IR，不产出 SQL 文本，因此不需要方言；
- `Build` 的 `ctx` 当前核心不使用（生成是纯内存计算），为自定义算子预留；
- 完整语句由 dbwm 渲染：`dbwm.Query{Table, Columns, Where: w}`。

## 6. 已知限制

1. **只覆盖单表 WHERE**：JOIN 之后的跨表条件、`or` / `and` 的跨表混排不在本文范围 —— 它会改变"列名允许重复"等前提；
2. **不支持子查询、函数表达式、原始 SQL 片段**：值一律是绑定参数；确实需要时注册自定义算子；
3. **默认是精确匹配**：标量字段恒参与条件（零值也参与，`id = 0`）；"不填就是不过滤"只对指针字段成立 —— 只想让零值被忽略，给字段加 `omit`；
4. **没有"运行时拼条件"的构造器**：条件必须由结构体表达（指针 + 结构体分组已能覆盖绝大多数场景）；
5. **`Range` 的零值边界表达不了**：`Range[int]{Min: 0, Max: 100}` 的 `Min = 0` 被当成"没给"→ 数值区间的 0 下界表达不了，退回两个普通字段（`op=gte` + `op=lte`）；备选 `Min *T / Max *T`（nil = 未给）构造啰嗦，用值边界；
6. **`like` 的模式由 ORM 补 `%`**：值里没有 `%` 时补成包含匹配（`%值%`）；要前缀/后缀匹配自己写 `"a%"` / `"%a"`（见 R4）；**不做 `%` 与 `_` 的转义** —— 要精确匹配用 `eq`；
7. **`isnull` / `notnull` 只能"要么加、要么不加"**：不能按字段值在 `IS NULL` / `IS NOT NULL` 之间切换 —— 要切换就用两个字段（两个算子各配一个 `*bool`）；
8. **没有列存在性校验**：条件里引用了行模型里不存在的列，本层不报错（JOIN 场景下别的表的列也是合法的）—— 由上层在确定无 JOIN 时再校验；
9. **`omit` 在不同算子下效果不同**：对标量 / 指针有效；对 `Range`、`isnull` / `notnull`、空切片无额外效果（天然跳过）—— 解析期不报错（见 3.2）；
10. **空切片不生成条件**：不会出现 `IN ()` 这种非法 SQL —— 但也意味着"空集合"与"不限"无法区分。

## 8. 实现参考（代码结构）

> 本节是实现指引，不是需求约束。目标布局沿用写包的分工原则：**一个包一个能力，按关注点分文件**。

```
util/                       共享：标签文本工具 + 取值与零值 + 区间类型（方言在 dbwm）
  util.go      包注释与文件分工说明
  tag.go       dbx 标签的文本处理（切分、选项解析、去引号、snake_case）
  value.go     取值、零值判定、单列类型识别、sql.Null* 取值
  range.go     Interval 接口 + Range[T any]

query/                      只做查询条件（包名 query：select 是 Go 关键字）
  query.go     对外 API（ParseWhere / Template）
  option.go    读规则的选项名与校验
  operator.go  算子表、算子注册（重名 panic）、按类型推断与校验
  parse.go     条件结构体 → 条件树模板（解析期，按类型缓存）
  where.go     运行期取值 + 条件树生成（Wnode 组装、区间展开）
```

> 查询侧不碰数据库（生成条件树是纯内存计算），因此没有 `deps.go`；
> 行模型（列清单推导、扫行回结构体）在 `select/`（包名 `rows`）与 `model/`，见 [prd-slyorm.md](prd-slyorm.md)。

**落地时同步做的三件事**（已完成）：

1. 标签文本工具（切分、选项解析、去引号、snake_case）归 `util`，读写共用一份实现，切分规则只有一处；
2. 方言归 `dbwm`（见 [prd-dbwm.md](prd-dbwm.md) R2）—— 查询包产出 IR 不产出 SQL 文本，不再需要方言；
3. 单列类型表登记 `Range[T]`（写规则已把它列为单列类型，见 [prd-insert.md](prd-insert.md) R3 ①）—— `Range` 是一个条件，不是嵌套结构，**不得按 `inline` 展开**。

其它约束：

- `util` 只放**文本级**工具与公共类型，不含"选项是什么意思"的语义 —— 语义解释仍各包自己来；
- `query` 不 import 写包：两个能力互不依赖；
- 条件树模板（`parse.go` 产物）存**原始列名**，引号由 dbwm 渲染时加 —— 同一模板跨方言复用（见 R6.5）。
